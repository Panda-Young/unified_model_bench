## 权重统计优化：TFLite 精确解析（文件近似 → buffer 精确）
- 现状评估：ONNX（protobuf initializer 解析）与 NCNN（.ncnn.bin 即权重）本就精确；
  **TFLite/MNN/QNN 用整个文件大小近似**（含图结构/元数据开销）。TFLite 是主流格式且
  flatbuffer 结构公开 → 值得优化；MNN（.mnn 自定义复杂 schema）与 QNN（context binary
  私有格式）保持近似（代码注释说明理由）。
- 实现（src/model_loader.cpp，零依赖 minimal FlatBuffers reader）：
  - `FbReader`：u32/i32/u16 + `table_field(t, fidx)`（vtable 定位）
  - `tflite_weights_bytes()`：root table（文件开头 uoffset，相对自身）→ Model.buffers
    (field 4, uoffset 间接) → vector 元素（Buffer table，uoffset 相对元素槽）→
    Buffer.data (field 0, uoffset 间接) → 求和
  - estimate_weight_mb 的 TFLite 分支：解析成功用精确值，失败回退文件大小
- **flatbuffer 布局踩坑（重要经验）**：
  1. root table 在文件开头（u32@0 相对自身），**不是**标准"末尾 4 字节 root offset"布局
  2. vtable 偏移 soffset = table - vtable 的**有符号距离**（可正可负，实测 root +20、
     buffer -4716），统一公式 `vtable = table - ReadInt32(table)`
  3. 字段存在条件：`vtable_size >= 4 + (field_index+1)*2`（vsz=4 表示无字段，曾误读垃圾）
  4. 所有 vector 字段都是 uoffset 间接：vector 起点 = 字段位置 + uoffset；
     vector 内元素 uoffset 相对**元素槽自身**（不是 vector 起点）
- 验证：先用 `pip install tflite`（官方 schema 生成的 python 模块）做权威基准——
  test_model.tflite 权重 = **186,344 B**（29 buffers，与 .ncnn.bin 的 186,240 一致，
  差 104 B 附加常量）；文件近似 191,612 B（多报 5.4 KB）。C++ 实现逐项 size 数组与
  权威库完全一致。单测新增 TFLite 用例（与 NCNN 权重一致性 <5% 断言）。
- 全套验证：30/30 单测通过（150,701 断言）、cl /Zs rc=0、check_braces TOTAL:0、
  Android（NDK r29 + Ninja）36/36 构建成功（含测试目标）。
- 备注：build/android-sync-check 验证目录本次 rm 被沙箱 bulk-delete 拦截（71 文件），
  留在 build/ 下无害，可手动删除。
